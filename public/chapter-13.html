CHAPTER 13: MOBILE WIRELESS ATTACKS AND REMEDIATION

SECTION 1: SCANNING THE CORPORATE NETWORK

🔑 WHY SCAN THE NETWORK?

Definition: The prevalence of mobile devices has created many security issues, such as data leakage and backdoors.

Key Points:

  • Employees bringing jailbroken, rooted, or compromised devices into the network create a gateway for cybercriminals to exploit the devices and the network.
  • Security professionals must regularly scan for unauthorized smart devices.
  • The Challenge: IT teams must scan known networks and unauthorized ad hoc networks (mobile hotspots, Bluetooth connections).
  • Good News: Device manufacturers are reducing the attack surface (the sum of all potential attack routes), resulting in fewer direct device attacks.

Real-World Example:

Think of a compromised device like an unlocked back window in a house. It doesn't just risk the room it's in—it risks the whole house (the corporate network).

🔑 SECURITY AWARENESS (THE USER PROBLEM)

Definition: Developers often overestimate the general public's technical literacy.

Key Points:

  • Users may not understand what WPA, WPA2, or WPA3 are when configuring Wi-Fi.
  • The problem is compounded by smartphones, tablets, and wearables leaving and re-entering the premises daily.
  • Tracking authorized devices is hard enough without tracking unauthorized devices connecting via hotspots, ad hoc, or Bluetooth.

Real-World Example:

Think of security options like a car's dashboard. Engineers know what all the lights mean, but the average driver just wants the car to go. If they don't understand it, they might choose the wrong (insecure) setting.

📊 SCANNING THE NETWORK: WHAT TO LOOK FOR

Definition: The first step is to scan the 2.4 GHz and 5 GHz unlicensed bands to discover communicating entities.

From Discovered Access Points (APs):

Data CollectedDescription
MAC AddressThe physical address of the AP.
ESSIDExtended Service Set Identifier (the network name).
ChannelsThe 20MHz and 40MHz channels in use.
Signal-to-Noise RatioAverage and peak SNR.
Power LevelsHow strong the signal is broadcasting.
Network Type802.11a/b/g/n.
Beacon Security ParametersWEP, TKIP, AES-CCMP.
LocationPhysical location of the AP.

From Discovered Wireless Stations (Clients):

Data CollectedDescription
Associated APsWhich AP or peer station the client is connected to.
802.1X IdentityThe identity used for RADIUS authentication (credential or certificate).

Why Collect This?

  • Admins: Compare inventories to uncover discrepancies.
  • Attackers: Use this info to explore weaknesses.
  • Rogue-device challenge: Finding and removing rogue devices can be difficult because they may belong to neighbors, vendors, guests, or employees.
  • Ideal WIPS setup: Use centralized control and a reporting console, with distributed wireless intrusion-prevention agents on every wireless segment.

🔑 SCANNING FOR VULNERABILITIES

Definition: Wireless scanning is not just about finding rogue devices; it's about verifying that authorized APs have security measures in place.

What to Check on Access Points:

  • Latest firmware and security patches.
  • Correct security credentials.
  • Appropriate security protocols.
  • Encrypted administration interfaces.
  • Appropriate protocol filters.
  • Vulnerability to common attacks (e.g., DoS via authentication floods).

What to Check on Authorized Smartphones/Tablets:

  • Latest OS and security patches.
  • Default Re-association: Smartphones default to re-associating with previously connected SSIDs (a weakness).
  • Network Bridging: A smartphone may simultaneously connect to mobile (cellular) and Wi-Fi networks, effectively bridging two independent networks.
  • Automatic cloud backups: Phones may automatically back up data to iCloud, Google Cloud, OneDrive, or Azure. This can create another route for corporate data to leak outside the network.
SECTION 2: KALI LINUX & NETWORK IMPERSONATION

🔑 THE KALI LINUX SECURITY PLATFORM

Definition: An open-source security platform built on Linux (single-user root access) that hosts a multitude of security and penetration testing tools.

Tool Categories:

  • Information gathering
  • Vulnerability analysis
  • Wireless attacks
  • Web applications
  • Exploitation tools
  • Forensics
  • Stress testing
  • Sniffing and spoofing
  • Password and hardware hacking

Key Point: Kali Linux includes Metasploit, Aircrack-ng, and more than 300 other penetration-testing tools.

📊 SCANNING WITH AIRODUMP-NG

Definition: Part of the Aircrack-ng suite. It is used to scan wireless networks and return specific data for each discovered device.

Output FieldDescription
BSSIDBasic Service Set Identification (association with a station).
ESSIDExtended Service Set Identification (the network name).
MAC AddressUnique ID for each AP and station.
ProbeThe network the station is trying to reach.
Power LevelBroadcast level (higher power = better chance to crack password).
CipherWEP, CCMP, or TKIP.
AuthenticationPSK, RADIUS, or None.

⚠️ NETWORK IMPERSONATION (EVIL TWIN)

Definition: The attacker impersonates an AP by broadcasting an identical SSID on an interface with boosted power.

How It Works:

  1. Attacker broadcasts identical SSID with stronger radio power than the genuine AP.
  1. Attacker sends deauthorization packets to force the original AP to drop client associations.
  1. Clients always favor the stronger signal, so they connect to the rogue AP.
  1. All communication flows through the attacker's AP.

What the Attacker Can Do:

  • Run any Man-in-the-Middle (MITM) exploit.
  • Spoof DNS queries.

Real-World Example:

Think of Network Impersonation like a fake Wi-Fi hotspot at an airport. It looks exactly like the real one but has a stronger signal, tricking your phone into connecting to it instead.
SECTION 3: CLIENT-SIDE & USB EXPLOITS

🔑 CLIENT-SIDE EXPLOITS

Definition: As Wi-Fi becomes more secure, attackers shift to client-side exploits via malware (attachments, downloads, web browsing, USB connections).

The Attack Chain (Example):

  1. Social Engineering: Attacker gathers email addresses and information.
  1. Forged Email: Attacker uses a trusted partner's email address as the source of a forged email.
  1. Payload Construction: Uses Metasploit exploits (e.g., Adobe util.printf, targeting Adobe Reader) to create a payload disguised as a .pdf file.
  1. Reverse Connection: The file executes a reverse TCP/IP connection back to the attacker's machine to load a USB exploit.
  1. Remote Control: Program gains remote control of the USB ports, allowing the attacker to take control of a smartphone when attached to the port.

Detection: A WIPS should be able to detect traffic anomalies and raise an alarm.

Real-World Example:

Think of this attack like a Trojan horse. A seemingly harmless PDF is opened, but it secretly opens the gates (reverse TCP connection) to let the attacker in.

⚠️ OTHER USB EXPLOITS

Definition: Smart devices' vulnerability lies in the handshake between the USB port and the device when connected.

How It Works:

  • The handshake determines what the plugged-in device is.
  • Rogue USB Device: A rogue device might claim to be a Human Interface Device (HID) like a keyboard. All keystrokes typed on the infected PC are then forwarded to the connected USB device.
  • The Problem: USB standards allow a casual and transient association, making the connection between a vulnerable PC and a tethered smartphone dubious.
  • Attacker's Path: Infect weak PC clients first → gain direct control → infect smartphones/tablets when they use the USB connection.

Real-World Example:

Think of a USB exploit like a fake keyboard plugged into your PC. It looks like a keyboard, but it's actually typing commands to steal your data.
SECTION 4: NETWORK SECURITY PROTOCOL EXPLOITS

🔑 RADIUS IMPERSONATION

Definition: An attacker sets up a fake AP and RADIUS server to intercept and capture client login credentials.

Tool Used: FreeRADIUS (passes RADIUS authentication requests to a rogue host).

How It Works:

  1. Attacker sets up fake AP and RADIUS server.
  1. Waits for clients to authenticate.
  1. Captures the challenge-and-response traffic between the RADIUS server and the client.
  1. Although content is encrypted, the cipher can be broken using password-cracking tools.
  1. Attacker obtains user account and password → accesses sensitive data.

Why It Works: Self-signed certificates are used in the 802.11 environment and installed on the RADIUS server.

Remediation: Use EAP-TLS. It uses mutual authentication (client authenticates to server, and server authenticates to client), making it immune to this attack.

🔑 PUBLIC CERTIFICATE AUTHORITY (CA) EXPLOITS

Definition: Certificates are used for authentication (banking, retail) to assure clients the site is who they claim to be.

The Weakness: Many mobile applications are deployed without requiring a check of SSL certificate validity. (Browsers enforce this strictly and throw warnings; apps often don't).

The Attack: An attacker uses a forged certificate to launch MITM attacks on banking and e-commerce sites.

Example: The Heartbleed security vulnerability discovered in OpenSSL in early 2014.

🔑 DEVELOPER DIGITAL CERTIFICATES

Definition: Certificates are used to verify that an app has not been tampered with (encrypted digital signature in the code).

The Weakness: Enterprise developer certificates can be stolen and sold on the black market, or forged and used to sign malicious applications.

🔑 BROWSER APPLICATION & PHISHING EXPLOITS

Definition: Indirect attacks that have existed for years on PCs and are essentially unchanged on mobile devices.

Captive Portals:

  • Used to validate guest users and communicate terms of use.
  • Vulnerability: Can be used to launch MITM attacks and steal credentials.
  • Example: A cybercriminal in a shopping mall routes clients to a captive portal. Users enter credentials, and the portal acts as a real hotspot. Alternatively, it allows access only after the user downloads a client-side PDF attack (Adobe Reader exploit).

Drive-by Browser Exploits:

  • Target web browser plug-ins (Java, Adobe Reader, Flash).
  • Launched via legitimate but compromised websites that infect mobile clients.
  • Example Tool: Browser Exploitation Framework (BeEF) on Kali Linux.
  • Mechanism: Script is embedded in the compromised webpage. Requires victim to visit the site.
  • Defenses: Keep browsers/plug-ins up to date, harden websites, disable JavaScript plug-ins (but degrades experience).
SECTION 5: MOBILE SOFTWARE EXPLOITS & REMEDIATION (OWASP TOP 10)

🔑 OWASP

Definition: Open Web Application Security Project — an international foundation dedicated to enabling organizations to develop secure applications.

📊 OWASP TOP 10 MOBILE RISKS (AND REMEDIATIONS)

RiskDescriptionRemediation
1. Weak Server-Side SecurityAllows injection of malicious code to infect the mobile browser using drive-by exploits. Exploits web interfaces/APIs.Use applications from trusted sources with a reputation for secure software.
2. Unsecure Data StorageSensitive data stored in locations with no/inadequate security. Leads to data loss, fraud, stolen credentials. Exploited through malware.iOS: Never store credentials on file system; use secure encryption library; use secure API for keychain; layered encryption; SQLCipher for SQLite. Android: Use enterprise admin API to force encryption; master password + AES-128; layered encryption; do NOT set shared preferences to Mode_World_Readable.
3. Insufficient Transport Layer ProtectionApps use SSL/TLS for login, then revert to cleartext HTTP. Vulnerable to MITM and eavesdropping.Ensure digital certificates are valid; use secure transport APIs in all cases; do NOT allow self-signed certs; Android devs must remove code that accepts all certificates.
4. Unintended Data LeakageDevelopers inadvertently place sensitive data in easily accessible storage.Check URL, copy/paste, keyboard caching; check HTML5 data storage; check browser cookies; check analytics sent to third parties.
5. Poor Authorization and AuthenticationInsufficient mechanisms allow attackers to execute functions. Caused by simple auth schemes on mobile screens.Enforce server-side authentication mechanisms; don't rely on user-side auth.
6. Broken CryptographyWeak encryption can be captured and cracked. iOS issue: Rogue dev can load app on jailbroken device and snapshot decrypted code from memory.Do NOT rely on built-in code encryption; manage keys securely; do NOT use deprecated algorithms (MD4, SHA-1).
7. Client-Side InjectionExecution of malicious code on mobile app. (Moderate risk because client code runs with user permissions).Check for SQL injection, JavaScript injection, Local File Inclusion, XML injection, Classic C attacks (strcat, strncat, sprint, gets).
8. Security Decisions via Untrusted InputsApps access data from many sources via Inter-Process Communication (IPC). Open communication is a weakness.Sandbox approach: only allow apps to interact if there is a pressing business requirement; require user intervention for sensitive data; strict validation of external input; do NOT use Apple Pasteboard for IPC (readable by all apps).
9. Improper Session HandlingHTTP is stateless, so sessions must be handled. Failing to invalidate sessions creates an exploit window.Invalidate sessions on server side and mobile device. Rotate cookies and tear down/re-create sessions when: user switches anonymous to logged on, change in logged-on users, switch to elevated account, after session timeout.
10. Lack of Binary ProtectionsBinary hardening prevents reverse engineering and tampering.Ensure code adheres to secure coding (jailbreak detection, checksum controls, certificate pinning controls, debug detection). App must determine time of execution if there is a code-integrity violation.

Memory Aid for OWASP Top 10:

"Weak Server, Unsecure Storage, Poor Transport, Leakage, Poor Auth, Broken Crypto, Injection, Untrusted Input, Bad Sessions, No Binary Protection."

✅ THE CORE TRUTH
Mobile attacks have shifted from infrastructure to clients. Attackers use social engineering, malicious USB devices, and fake RADIUS servers to compromise credentials. The OWASP Top 10 provides a roadmap for developers to secure mobile apps, but the ultimate defense is a combination of user awareness, network scanning, and secure coding practices.
