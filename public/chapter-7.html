CHAPTER 7: BASIC WLAN SECURITY MEASURES

SECTION 1: DESIGN & IMPLEMENTATION CONSIDERATIONS

🔑 RADIO FREQUENCY DESIGN

Definition: RF waves travel through walls and windows and leak into the outside world. The goal is to restrict RF coverage to the premises' boundaries.

Key Points:

  • Why restrict RF coverage?
    • Provides physical security.
    • Avoids polluting neighboring wireless networks.
  • Use wireless repeaters instead of access points to boost signals (not increase power).

Real-World Example:

Think of RF leakage like light spilling out of a window. You want to light up your room, not the whole street. Use curtains (lower power, directional antennas) to keep it inside.

🔑 EQUIPMENT CONFIGURATION AND PLACEMENT

Definition: Consider the antenna type and coverage pattern when placing equipment.

Key Points:

  • Omnidirectional antenna: Transmits in all directions (360-degree coverage). Supports a large area.
  • Placement tip: Place omnidirectional antennas at a central location — not near an external window.

Real-World Example:

Think of an omnidirectional antenna like a ceiling light. Put it in the center of the room, not next to a window, or you'll waste light (signal) outside.

📊 AZIMUTH (HORIZONTAL) AND ELEVATION (VERTICAL) SIGNAL DISTRIBUTION

Definition: Antennas radiate differently on the horizontal plane (azimuth) and vertical plane (elevation).

The Two Patterns:

PatternDirectionShapeWhat It Shows
Azimuth (Horizontal)Left to right (0°–360°)Nearly circular (for omnidirectional)Coverage around the antenna.
Elevation (Vertical)Up and down (0°–180°)Figure-eight or donut shapeCoverage above and below the antenna.

Key Observation:

  • For an omnidirectional antenna at 2.4 GHz:
    • Azimuth = 360° (full circle).
    • Elevation = a "donut" shape (signal is strongest horizontally, weaker directly above/below).

Memory Aid:

"Azimuth = Around. Elevation = Up and Down."

🔑 INTEROPERABILITY AND LAYERING

Definition: Delivering RF coverage in a building is difficult and unpredictable. The most common way to check is to walk the premises with a tablet or laptop to measure received signal strength.

Key Points:

  • Dead spots: Spots where the signal does not reach.
    • Solution 1: Increase power setting.
    • Solution 2: Adjust AP position.
  • Wireless Extender/Repeater: Uses the same frequency and channel to overlap the original BSS coverage by 50% — increases reach/coverage by half.
  • Twin Access Points: Use the same SSID and non-interfering channels to overlap 100% connection.

Real-World Example:

Think of a wireless repeater like a relay runner in a race. The first runner (AP) hands the baton to the second runner (repeater), who carries it further.

Memory Aid:

"Repeater = 50% overlap. Twin APs = 100% overlap."

🔑 SECURITY MANAGEMENT

Definition: When managing wireless networks from a security perspective, it is important to have detailed knowledge of all available security tools and techniques. No one-size-fits-all design.

Two Scenarios:

ScenarioOrganization TypeKey Criteria
1PR/Internet marketing agencyReliability, quality, availability of VoWLAN calls.
2Mobile telephone resellerAuthentication and encryption (to secure hundreds of thousands of prepaid vouchers).

Key Takeaway:

Specific requirements and characteristics should always be considered. What works for one network may not work for another.

🔑 BASIC SECURITY AND BEST PRACTICES (SOHO)

Definition: Basic security best practices for Small Office/Home Office (SOHO) networks.

The 8 Best Practices:

PracticeDescription
1. Limit RF leakageLower the transmission power of access points.
2. SSID cloakingHide the network name.
3. WPA2 or WPA3 encryptionUse with a strong passphrase.
4. AuthenticationRequire users to prove identity.
5. MAC filteringAllow only known devices.
6. Locked closetKeep access points physically secure.
7. Firmware patchesRegularly check for and install updates.
8. Document everythingThis is called a risk assessment.

Memory Aid:

"Limit, Cloak, Encrypt, Authenticate, Filter, Lock, Patch, Document."
SECTION 2: AUTHENTICATION AND ACCESS RESTRICTION

🔑 SSID OBFUSCATION/SEGMENTATION

Definition: By assigning an SSID to a Virtual LAN (VLAN) , the administrator provides a method to segment users by SSID/VLAN pairs.

Key Points:

  • Commonly used in pre-Robust Security Network (RSN).
  • Defined in IEEE 802.11i security standard.
  • Typically three SSID/VLAN pairs are created:
SSID/VLAN PairPurposeNeeds
VoiceVoice trafficQoS (Quality of Service)
DataCorporate dataStrong security
GuestGuest accessInternet only, no security
  • Downside: The amount of work required to configure each individual access point.

Real-World Example:

Think of SSID/VLAN pairs like separate lanes on a highway. Voice has a fast lane (QoS), Data has a secure lane, and Guests have a slow lane (internet only).

🔑 SSID CLOAKING

Definition: The broadcast SSID option is disabled during configuration, effectively hiding the WLAN from unauthorized client stations by inhibiting the advertising of the SSID.

Key Points:

  • Cannot be discovered by passive or active scanning.
  • Can defeat tools like an insider with a modified active scanning process.
  • Protocol analyzers could defeat cloaking.
  • Clients must be pre-configured with the SSID. When a probe request with the pre-configured SSID is sent out, only then does the access point respond.
  • Security risks:
    • If an attacker can eavesdrop on the probe response, it can learn MAC, SSID, and BSSID.
    • User must enter SSID physically in the client device → subject to social engineering.
    • Friends/Guests may ask for the SSID.
  • Best for: Avoiding casual and opportunistic access.
  • Cannot protect from: A moderately skilled hacker.

Real-World Example:

Think of SSID cloaking like a hidden door. It stops casual passersby, but a determined person with a map (protocol analyzer) can still find it.

🔑 MAC FILTERS

Definition: Each MAC address is a unique six-byte number hardcoded into the network interface of each device capable of electronic communication. Works at OSI Layer 2 (Data Link Layer) .

Key Points:

  • MAC addresses = physical addresses. IP addresses = logical addresses.
  • Layer 2 = frames (not packets). MAC addresses identify source and destination.
  • MAC filters use a "deny by default, permit by exception" scheme.
  • Works well: Small networks like SOHO.
  • Not practical: Large networks or public networks.
  • Can be spoofed.
  • Like SSID cloaking, MAC filtering can avoid casual and opportunistic access.

Memory Aid:

"Deny by default, permit by exception."

Real-World Example:

Think of MAC filtering like a guest list at a party. Only people on the list get in, but someone could forge an invitation (spoof a MAC).

🔑 AUTHENTICATION AND ASSOCIATION

Definition: For a client station to join a network, it must go through the initial mandatory process of authentication and association.

Two Types:

TypeFull NameHow It WorksStatus
OSAOpen System AuthenticationAs long as SSID is known, client can access the network and receive non-encrypted information.Still in use.
SKAShared Key AuthenticationPart of WEP encryption. Client can access the network and send/receive encrypted data by matching the encryption key on the AP.Deprecated and not recommended.

Why SKA is Not Recommended:

  • Involves extra 2 message exchanges and 2 encryption/decryption operations during four-way handshake.
  • Challenge is in plaintext. Attacker can eavesdrop on both the challenge and the client's encrypted response.
  • Attacker can use the challenge-response in a replay message to try to expose the static keys.
  • The static key is also used to encrypt payload → attacker can break the encryption.

Challenge-Response Diagram (SKA):

Authenticator-AP                    Client-STA
      |                                  |
      |------ Challenge C₁ ------------->|
      |                                  |
      |<----- Response E_PSK(C₁) --------|
      |                                  |

Memory Aid:

"OSA = Open (no encryption). SKA = Shared Key (deprecated, replay attack)."

🔑 VPN OVER WIRELESS (HISTORICAL)

Definition: Before 2007, VPN over wireless was commonly used for securing user connections.

Key Points:

  • Used for inter-building bridges and secure point-to-point connections.
  • Now discouraged because of high overhead and performance issues.
  • Downside: VPNs operate at Layer 3 — attacker can get access to both Layer 2 and Layer 3 connections before the VPN tunnel is established.
  • After 2007, Layer 2 security solutions were provided.
  • WEP was adopted for Layer 2 but double encryption created overhead and impacted performance.

Real-World Example:

Think of VPN over wireless like wearing a raincoat over your clothes. It works, but it's bulky (overhead), and you're still wet underneath (Layer 2 is exposed).

🔑 VIRTUAL LOCAL AREA NETWORK (VLAN)

Definition: VLAN specifies broadcast domains — logical segments of the network that receive the same broadcast messages over the shared medium.

Key Points:

  • By creating VLANs, an administrator restricts broadcasts to individual VLAN members and provides isolation from other VLANs.
  • 802.1Q tagging: VLAN ID inserted into packet header to identify packets as being in a particular VLAN.
  • Communication between VLANs is bridged via routers.
  • QoS can be defined on a per-VLAN basis to give priority to certain traffic types (voice, video, etc.).

Real-World Example:

Think of VLANs like separate floors in a building. People on Floor 1 can't hear people on Floor 2 (isolation), but they can take the stairs (router) to visit each other.

📊 VLAN IS LOGICAL PARTITIONS (DIAGRAM 1)

The Flow:

Router

  ├── Switch ── Engineering VLAN ── Floor 3, Floor 2, Floor 1
  ├── Switch ── Marketing VLAN ──── Floor 3, Floor 2, Floor 1
  └── Switch ── Accounting VLAN ─── Floor 3, Floor 2, Floor 1

Key Observation:

  • Each department (Engineering, Marketing, Accounting) has its own VLAN.
  • VLANs span multiple floors (logical, not physical).
  • Router connects the VLANs.

"VLAN = Logical, not Physical. Same department, different floors."

The Flow:

  • VLAN 30 (IoT): Isolated, for IoT devices.
  • Isolation: No direct traffic between VLANs.

Memory Aid:

"Guest, Corporate, IoT — three VLANs, three SSIDs, one core switch."
SECTION 3: DATA PROTECTION

🔑 DATA PROTECTION OVERVIEW

Definition: Wireless traffic is available to anyone within the reach of the radio signals. Security professionals must protect both data and authentication credentials via encryption.

The Four Protocols (in order of strength):

ProtocolFull NameStrength
WEPWired Equivalent PrivacyWeakest
WPAWi-Fi Protected AccessBetter
WPA2Wi-Fi Protected Access 2Strong
WPA3Wi-Fi Protected Access 3Strongest

Memory Aid:

"WEP → WPA → WPA2 → WPA3 — each one stronger."

🔑 WIRED EQUIVALENT PRIVACY (WEP)

Definition: The goal of WEP was to provide confidentiality, integrity, and access control for wireless networks.

Key Points:

  • Defined in the original IEEE 802.11 standard in 1997.
  • Data privacy: Through encryption.
  • Access control: Via static-key form of authentication.
  • Data integrity: Through a checksum.
  • Static WEP key was also used to encrypt Layer 3 payload.

Two Key Versions:

VersionSecret Static KeyIVTotal Key Size
64-bit WEP40-bit24-bit64 bits
128-bit WEP104-bit24-bit128 bits

IV (Initialization Vector): Locally generated random number of 24-bit, appended at the end of the key.

Weaknesses of WEP:

WeaknessDescription
Static keySame key used for all devices.
IV collision attackIf IV is reused, the same static key is repeated. By analyzing packets from the same keys, attacker can break WEP encryption in less than 5 minutes.

Memory Aid:

"WEP = Weak Encryption Protocol. Static key + IV reuse = broken in 5 minutes."

🔑 WI-FI PROTECTED ACCESS (WPA)

Definition: WPA was introduced by the Wi-Fi Alliance in 2003 to support TKIP/RC4 dynamic encryption key generation.

Key Points:

  • Viewed as an intermediate solution to address WEP weaknesses until WPA2 was available.

Improvements Over WEP:

ImprovementDescription
TKIPA stream cipher. Combined the secret encryption key with an IV before initiating RC4 initialization.
Sequence counterProtects against replay attacks.
64-bit MICMessage Integrity Check ensures messages have not been modified in transit.

Weaknesses of WPA:

AttackDescription
Beck-Tews attackMinor changes to packets encrypted with TKIP, then send back to AP. Checksum was not encrypted → exploited.
Ohagi/Mori attackImproves on Beck-Tews, lowers execution time to about one minute.

Key Point: Attacks were on data integrity, not on exposing the encryption keys.

Memory Aid:

"WPA = TKIP + RC4 + sequence counter + MIC. Better than WEP, but still broken."

🔑 WPA2

Definition: WPA2 is built on the AES algorithm in Counter Mode Cipher Block Chaining Message Authentication Code Protocol (CCMP) .

Key Points:

  • AES: Block cipher algorithm. Supports three key sizes: 128, 192, and 256 bits. Fixed block size of 128 bits.
  • CCMP: Security encryption protocol defined by 802.11i WPA2.
    • Data confidentiality via encryption.
    • Authentication.
    • Access control with layer management.
  • CCMP uses: Fixed block size of 128 bits, fixed key size of 128 bits.
  • Layer 2 protocol: Ensures information from Layer 3 to 7 is encrypted in the 802.11 data frame.
  • Layer 3 payload: Encrypted using AES, protected from manipulation by MIC.

Weakness of WPA2:

WeaknessDescription
Dictionary AttackAttacker uses a list of common passwords to guess the PSK.

Memory Aid:

"WPA2 = AES + CCMP + 128-bit keys. Strong, but vulnerable to weak passwords."

🔑 WPA3

Definition: In 2018, the Wi-Fi Alliance introduced WPA3, adding four new features to bolster WPA2.

The Four New Features:

FeatureDescription
1. Data privacy over public networksIndividualized data encryption. When you connect to an open Wi-Fi network, traffic between your device and the AP is encrypted.
2. Protection against brute force attacksNew handshake protocol delivers robust protection.
3. Easier connection for devices without displaysSimplify configuring security for devices with limited or no display interface.
4. Higher security for government, defense, industrialStronger and longer session key up to 192 bits.

Memory Aid:

"WPA3 = Individualized encryption, brute force protection, easy setup, 192-bit keys."

📊 WI-FI DATA PROTECTION METHODS — RECOMMENDATIONS (TABLE)

ProtocolEncryption / AuthenticationSecurity Status
WEPRC4, static key, 24-bit IVInsecure; obsolete.
WPATKIP/RC4Insecure; obsolete.
WPA2-PersonalAES-CCMP, PSKSecure with strong credentials and correct configuration.

"WEP and WPA = obsolete. WPA2 = secure. WPA3 = preferred."
SECTION 4: ONGOING MANAGEMENT SECURITY CONSIDERATIONS

🔑 ONGOING MANAGEMENT OVERVIEW

Definition: Any aspects of the network that are not actively monitored and managed become a potential vulnerability.

The Four Areas:

  1. Firmware upgrades
  1. Physical security
  1. Periodic inventory
  1. Identifying rogue WLANs/Wireless access points

🔑 FIRMWARE UPDATE

Definition: Firmware is a specific class of computer software that provides low-level control for a device's specific hardware.

Key Points:

  • Hacker's best practice: look for unpatched equipment.
  • When unpatched devices are found, there's often a "cookbook" approach to exploiting the unfixed issue.
  • Typical method of upgrading: Use an FTP server to download the firmware upgrade from the vendor's website.
  • Telnet: A network protocol that supports remote nonsecure access to another device. Also used.
  • This is a good example of central device management — a necessary and essential element of large network management.

Real-World Example:

Think of firmware updates like vaccines for your devices. Without them, your devices are vulnerable to known diseases (exploits).

🔑 PHYSICAL SECURITY

Definition: Physical security is an often-overlooked aspect of wireless security policy.

Key Points:

  • If devices have been pre-configured for wireless security, only legitimate wireless-enabled devices will be able to access the network.
  • Enterprise environment: Authentication methods make it easy to blacklist lost or stolen devices.
  • SOHO environment: If no such device management is in force, the administrator should change all passphrases and PSKs.
  • When an employee leaves: Not just retrieve their laptop — you must access their devices to remove Wi-Fi security configurations.
  • Good practice: Change PSKs and passphrases monthly.

Real-World Example:

Think of physical security like changing the locks when an employee leaves. If you don't, they still have the key (PSK).

🔑 PERIODIC INVENTORY

Definition: Keep an up-to-date inventory of all devices authorized to connect to the WLAN.

Key Points:

  • Must be aware of all devices and their respective MAC addresses to manage the access list.
  • Common to find anonymous devices using WLAN services.
  • Good idea: Create a guest VLAN with internet-only access.
  • Periodic inventory checks: SOHO network administrator can audit MAC addresses traversing the WLAN and identify them as known or unknown.

Real-World Example:

Think of periodic inventory like a guest list at a wedding. You know exactly who's coming, and if someone shows up who isn't on the list, you know something's wrong.

🔑 IDENTIFYING ROGUE WLANs/WIRELESS ACCESS POINTS

Definition: The best preventative measure for rogue access points is to conduct regular and frequent audits of all access points on the WLAN.

Key Strategies:

StrategyDescription
1. Manage Ethernet switch portsEnsure unused ports are disabled by default.
2. Limit RF coverageRestrict to the boundaries of the premises. Prevents installation of APs outside the building to eavesdrop.
3. Use RADIUSIf rogue APs continue to appear, configure one of the newer access points as a Remote Authentication Dial-In User Service (RADIUS) authentication server.

Real-World Example:

Think of rogue AP hunting like a security guard patrolling the building. Regular audits = regular patrols. You catch intruders before they do damage.

✅ THE CORE TRUTH
Basic WLAN security is built on proper design (restricting RF coverage, correct antenna placement), strong authentication (WPA3 preferred), access restriction (SSID cloaking, MAC filtering, VLANs), data protection (WEP → WPA → WPA2 → WPA3), and ongoing management (firmware patches, physical security, periodic inventory, rogue AP detection). No single measure is enough — security is layered.
