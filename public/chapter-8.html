CHAPTER 8: ADVANCED WLAN SECURITY MEASURES

SECTION 1: ESTABLISHING AND ENFORCING A COMPREHENSIVE SECURITY POLICY

🔑 WHY A SECURITY POLICY FIRST?

Definition: Before implementing any security techniques, the first task is to analyze the network's security requirements and decide on a security policy.

Key Point:

Policy first, technology second. You can't secure what you haven't defined.

🔑 COMMON POLICY COMPONENTS

Definition: Every enterprise security policy must address six common areas.

The 6 Policy Components:

ComponentDescriptionKey Considerations
1. Centralized vs Distributed DesignHow the network is managed.Centralized: Thin APs + centralized controllers. Distributed: Each AP configured separately.
2. Remote Access PoliciesHow remote users connect.(1) Uniform centralized authentication. (2) Permit VoIP/VoWLAN? (3) Secure VPN for telecommuters/travelers.
3. Guest PoliciesHow visitors access the network.Rules for visitor authentication and policy control.
4. QuarantiningIsolating a device until proven safe.Device is isolated until authorized AND free from malware.
5. Compliance ConsiderationsRegulatory requirements.A complete topic in itself (SOX, HIPAA, PCI DSS, GDPR, etc.).
6. Employee Training & EducationSecurity awareness.Always a good idea.

Memory Aid:

"C-R-G-Q-C-E" — Centralized, Remote, Guest, Quarantining, Compliance, Employee training.

Real-World Example:

Think of a security policy like a building's rules. Before you install locks (technology), you must decide: Who gets keys? Who can visit? What happens if someone breaks the rules?
SECTION 2: IMPLEMENTING AUTHENTICATION AND ACCESS CONTROL

🔑 IEEE 802.1X STANDARD

Definition: IEEE 802.1X specifies Port-based Network Access Control (NAC) for LANs and WLANs. It is a standalone authentication specification.

Key Points:

  • Central mechanism: Per-user and per-device authentication.
  • Process needs three entities.

The Three Entities:

EntityRoleAnalogy
SupplicantThe client device looking to connect to the network.The person wanting to enter a building.
AuthenticatorA network device (switch or access point). Acts as a gatekeeper.The security guard at the door.
Authentication ServerA server supporting an authentication protocol (EAP or RADIUS). Validates credentials.The back-office that checks the ID.

How It Works:

  1. Client sends credentials to the authenticator.
  1. Authenticator forwards them to the authentication server.
  1. Authentication server validates them.

Real-World Example:

Think of 802.1X like a nightclub entrance: You (supplicant) show your ID to the bouncer (authenticator), who calls the manager (authentication server) to verify you're on the list.

🔑 EXTENSIBLE AUTHENTICATION PROTOCOL (EAP) — PART I

Definition: EAP is a method of encapsulation used to securely transport keying material for encryption over wireless and Point-to-Point Protocol (PPP) networks.

Key Points:

  • Used over LANs between authenticator and authentication server → EAP over LAN (EAPoL).
  • Works by creating a secure tunnel using Transport Layer Security (TLS).
  • Generic authentication protocol to manage requests, challenges, notifications, etc.
  • EAP itself does not need to know the authentication credentials — can accommodate usernames, passwords, certificates, tokens, biometrics, etc.
  • LEAP (Lightweight EAP): Developed by Cisco prior to 802.11i. Unable to protect credentials, but widely adopted → many APs support it.

Memory Aid:

"EAP = Envelope for Authentication Protocols."

🔑 EXTENSIBLE AUTHENTICATION PROTOCOL (EAP) — PART II

Definition: Different EAP methods provide different levels of security.

Notation Table:

NotationExplanation
PMKPairwise Master Key
PTKPairwise Transient Key
GTKGroup Temporal Key
GMKGroup Master Key
ANonceNonce by AP
SNonceNonce by STA
MICMessage Integrity Code

EAP Methods:

MethodDescription
EAP-TLSGeneric interface. Uses PKI infrastructure (certificates). Strongest security.
EAP-MD5Uses Password Hash with MD5 and sends it with response.
EAP-PEAPTwo-phase authentication. The MIC is a direct derivative of the password (PTK), the two nonces, and the two MAC addresses.

EAPOL Key Message Structure (Diagram):

M₂: Message 2 (SNonce, Unicast, MIC₁)
M₃: Message 3 (Install PTK, MIC₂, Encrypted GTK)

FormulaDescription

MIC₂ = H(PTK, M₃)EAPOL-Key Message 3 with MIC field set to zero.
MIC₃ = H(PTK, M₄)EAPOL-Key Message 4 with MIC field set to zero.

PTK Formula:

PTK = PRF(PMK, ANonce, SNonce, MAC(AA), MAC(SA))

Memory Aid:

"EAP-TLS (certificates), EAP-MD5 (password hash), EAP-PEAP (two-phase)."

🔑 REMOTE AUTHENTICATION DIAL-IN USER SERVICE (RADIUS)

Definition: RADIUS is a network protocol that provides Authentication, Authorization, and Accounting (AAA) services for devices or users connecting to a network.

Key Points:

  • When a client attempts to connect, the device (or user) is challenged by a Network Access Server (NAS) device with a request for credentials (username/password).
  • The NAS passes credentials to the RADIUS server, which verifies them.
  • An access point with a built-in RADIUS client can communicate directly with both a client device and a RADIUS server.

Real-World Example:

Think of RADIUS like a central ID verification office. The security guard (NAS) takes your ID and calls the office (RADIUS server) to verify it. The office says "yes" or "no," and the guard acts accordingly.

The Flow:

│ Supplicant  │     │Authenticator│     │  RADIUS Server  │
│  (Client)   │     │ (Switch/AP) │     │ + Identity Store│
└──────┬──────┘     └──────┬──────┘     └────────┬────────┘
       │                   │                      │

       │                   │                      │
       │ 2. EAP-Req/Identity                      │
       │<──────────────────│                      │
       │                   │                      │
       │ 3. EAP-Response/Identity                 │
       │──────────────────>│                      │
       │                   │ 4. RADIUS Access-Request
       │                   │─────────────────────>│
       │                   │                      │
       │                   │ 5. RADIUS Access-Challenge
       │                   │<─────────────────────│
       │                   │                      │
       │ 6. Multiple EAP messages exchanged       │
       │<─────────────────>│<────────────────────>│
       │                   │                      │
       │                   │ 7. RADIUS Access-Accept
       │                   │<─────────────────────│
       │                   │                      │
       │ 8. EAP-Success    │                      │
       │<──────────────────│                      │
       │                   │                      │
       ▼                   ▼                      ▼
  (Port Authorized, Client Gains Network Access)

The 6 Steps (Simplified):

StepAction
1Client starts 802.1X — Supplicant sends EAPOL-Start to initiate authentication.
2Authenticator requests identity — Authenticator responds with EAP-Req/Identity.
3Client sends identity — Supplicant sends EAP-Response/Identity (e.g., username).
4RADIUS authentication exchange — Authenticator encapsulates EAP messages in RADIUS and forwards them to the server. Multiple EAP messages are exchanged (method-specific).
5Authentication result — RADIUS server sends Access-Accept or Access-Reject.
6Network access granted/denied — If accepted, authenticator opens the port and client gains network access.

RADIUS Messages (with EAP):

MessageDescription
Access-RequestCarries EAP-Message (e.g., EAP-Response/Identity).
Access-ChallengeCarries EAP-Message (e.g., EAP-Request).
Access-AcceptSuccess, with optional attributes (e.g., VLAN, ACL).
Access-RejectFailure, with optional attributes (e.g., reason, timeout).

Result:

  • Port becomes authorized by the authenticator.
  • Client gains network access (e.g., assigned VLAN).
  • Authorization attributes are applied (VLAN, ACL, QoS, session timeout).

Memory Aid:

"Start → Identity → Response → Exchange → Result → Access."

🔑 RADIUS BENEFITS

Definition: RADIUS provides centralized authentication for enterprise networks.

The 6 Benefits:

BenefitDescription
1. Centralized AuthenticationProvides a centralized system for authenticating users across multiple network devices (APs, switches, VPN gateways).
2. Reduced Administrative OverheadCentralized user management eliminates the need for separate authentication databases on individual devices. When an employee leaves, disabling their account centrally prevents further authentication.
3. AAA SupportCentralized Authentication, Authorization, and Accounting. Record session activities (login times, session duration, data usage) for monitoring, auditing, and compliance.
4. ScalabilityA single RADIUS server can manage authentication requests from numerous network devices — suitable for large enterprise networks.
5. Dynamic Access ControlAssign network privileges dynamically (VLAN membership, access control policies, session timeouts) based on user identity or organizational policies.
6. Reduced Administrative Overhead(Repeated — centralized user management eliminates separate databases.)

Memory Aid:

"Centralized, Reduced, AAA, Scalable, Dynamic, Reduced."
SECTION 3: INTRUSION DETECTION AND PREVENTION

🔑 IDS vs IPS

Definition: IDS and IPS are essential components in today's wired and wireless networks. Both work by using deep packet inspection to look inside packets traversing the network.

SystemFull NameWhat It DoesAnalogy
IDSIntrusion Detection SystemPure detection system. Raises a flag if it detects suspicious activity.A security camera — it records but doesn't stop the thief.
IPSIntrusion Prevention SystemActively confronts and blocks suspicious traffic.A security guard — stops the thief.

Key Points:

  • Both wired and wireless IPSs use known signatures of existing threats to identify attacks.
  • A wireless IDS or IPS is commonly referred to as a WIPS.

🔑 TYPES OF WIPS

Definition: There are two types of Wireless Intrusion Prevention Systems.

TypeDescriptionHow It Works
Network-based WIPSSensors that are either in line or configured in promiscuous mode to sample and analyze all traffic crossing the network.A centralized server and console analyze and present results.
Host-based WIPSAn application loaded onto a server or client computer/device.Monitors applications, operating systems, files, and known suspicious behavior.

What WIPS Mitigates:

  • Man-in-the-middle attacks
  • Rogue access points or evil twins
  • Unauthorized associations
  • MAC spoofing
  • Ad hoc networks
  • DoS attacks
  • Protocol misuse

Memory Aid:

"Network-based (sensors) vs Host-based (software)."

SECTION 5: DATA PROTECTION IN ENTERPRISE NETWORKS

🔑 802.11i STANDARD

Definition: The 802.11i standard security amendment came about as a result of inherent weaknesses in data-protection schemes.

Key Requirements:

  • 802.1X for authentication.
  • AES-CCMP for confidentiality and integrity.

Memory Aid:

"802.11i = 802.1X + AES-CCMP."

🔑 WPA2 AND WPA3

Definition: WPA2 has Personal and Enterprise modes; WPA3 improves upon WPA2.

WPA2 Personal vs Enterprise:

ModeWho It's ForHow It Works
WPA2-Personal (PSK)Small offices and home users.Pre-Shared Key.
WPA2-EnterpriseLarger organizations.RADIUS-based authentication (user credentials in RADIUS server).

⚠️ PASSWORD CRACKING IN WPA2

Definition: When a user connects to an open network, the initial "handshake" is visible to anyone listening. An attacker can capture it and take it offline.

The Attack:

  • Attacker runs billions of password guesses against the captured handshake at high speed using powerful computers.
  • This is known as an offline dictionary attack.
  • If the password is weak, it will eventually be cracked.

Real-World Example:

Think of an offline dictionary attack like stealing a locked safe and taking it home. You can try millions of combinations without anyone stopping you.

🔑 WPA3 — FOUR IMPROVEMENTS OVER WPA2

ImprovementDescription
1. Secure HandshakeSAE (Simultaneous Authentication of Equals).
2. Easy Device AdditionDPP (Device Provisioning Protocol) with QR codes.
3. Hotspot ProtectionBasic protection when using public hotspots.
4. Increased Key Sizes192-bit mode for enterprise.

🔑 WPA3 IMPROVEMENTS — PART I (SAE HANDSHAKE)

Definition: WPA3 uses a secure handshake called Simultaneous Authentication of Equals (SAE) .

How SAE Works:

  • Both the client and the access point prove to each other that they know the password without actually transmitting the password, even in encrypted form, over the air.

The Key Benefit:

  • Because the password is never used directly in the visible handshake, an attacker who captures the entire exchange cannot use it for an offline dictionary attack.
  • Each authentication attempt is interactive with the AP, which can rate-limit guesses, making brute-force attacks computationally infeasible.
  • Even if the network uses a simple password, it is vastly more resistant to cracking.

Memory Aid:

"SAE = Prove you know the password without saying it."

🔑 WPA3 IMPROVEMENTS — PART II (DPP WITH QR CODES)

Definition: Device Provisioning Protocol (DPP) makes it easy to securely add new IoT devices to a network.

The Problem: Connecting smart IoT devices is often hard and insecure, relying on weak methods like WPS pins or sharing your main Wi-Fi password.

The Solution — DPP with QR Codes:

StepAction
1. SCANScan a QR code on the new IoT device using your smartphone. Contains device's unique digital signature (public key), not the password.
2. AUTHENTICATESmartphone and device securely verify each other's identity using cryptography.
3. CONNECTUse a one-time access key received from the smartphone directly to the device to join the network.

Key Benefits:

  • No Passwords: Never type or share your main Wi-Fi password.
  • Unique Keys: Each device gets its own key. Compromising one doesn't risk the whole network.
  • Easy Revocation: Remove individual devices without changing the password for everything else.
  • No More Weak WPS: Replaces the insecure WPS pin method with a robust, standardized process.

Memory Aid:

"Scan, Authenticate, Connect — no passwords needed."

🔑 WPA3 IMPROVEMENTS — PART III (HOTSPOT PROTECTION)

Definition: WPA3 provides basic protection when using public hotspots.

Key Points:

  • On a WPA3-encrypted public hotspot, the initial connection is more secure due to SAE.
  • Makes it much harder for an attacker to crack the Wi-Fi password and eavesdrop on the initial handshake.
  • Important limitation: WPA3 does not encrypt the data between you and the hotspot router.
  • Once connected, your internet traffic is still visible to the network operator and could be intercepted by others on the same local network.
  • A WPA3 hotspot is safer to connect to, but it does not make the network itself safe for sensitive tasks.
  • You still need a VPN for true privacy.

Memory Aid:

"WPA3 protects the handshake, not the data. VPN for true privacy."

🔑 WPA3 IMPROVEMENTS — PART IV (192-BIT MODE)

Definition: WPA3-Enterprise 192-bit Mode offers an optional, higher-security mode with a consistent suite of robust cryptographic tools.

What "192-bit" Means:

  • All components meet a 192-bit security level.
  • Mandates the use of:
    • AES-GCMP-256 for encryption (instead of AES-CCMP).
    • GMAC-256 for data integrity.
    • ECDH-384 and ECDSA-384 for key exchange and authentication.
    • SHA-384 for hashing.

Key Benefit:

  • Provides a standardized, high-security floor for sensitive enterprise and government networks.
  • Ensures protection by a suite of algorithms resistant to known attacks.
  • Aligns with modern cryptographic standards.

Memory Aid:

"WPA3 192-bit = GCMP-256, GMAC-256, ECDH-384, ECDSA-384, SHA-384."

🔑 WPA3 — SIMULTANEOUS AUTHENTICATION OF EQUALS (SAE) TECHNICAL DETAILS

Definition: WPA3-SAE uses a pre-handshake mechanism to share the PMK of 256 bits.

Key Technical Points:

  • The low-entropy user password along with a counter (or SSID and MAC) is converted into a point (Map-to-Point) over a selected Elliptic Curve (PWE).
  • The SAE handshake provides forward secrecy and resistance against offline dictionary attacks.
  • Map-to-Point is an irreversible function — computationally infeasible for an attacker to extract the password from PWE.
  • Uses Management Frame Protection (MFP) to protect against de-authentication attacks.
  • Can work in downgrade mode to accommodate older devices.
  • Robust Security Network Element (RSNE) is verified using WPA2 handshake.

SAE Handshake Diagram (Simplified):

     STA                                          AP
      │                                            │
      │  Password → PWE                            │  Password → PWE
      │                                            │
      │  Commit-SAE(sA, EA)                        │
      │───────────────────────────────────────────>│
      │                                            │
      │  Commit-SAE(sB, EB)                        │
      │<───────────────────────────────────────────│
      │                                            │
      │  Confirm-SAE(CA)                           │
      │───────────────────────────────────────────>│
      │                                            │
      │  Confirm-SAE(CB)                           │
      │<───────────────────────────────────────────│
      │                                            │
      ▼                                            ▼
   Verify CB                                    Verify CA

Result: Size of k is 512 bits. STA and AP use 256 bits of k as PMK for successive sessions.

Memory Aid:

"SAE = Commit, Confirm, Verify. Forward secrecy, no offline dictionary."
SECTION 6: IPSEC

🔑 INTERNET PROTOCOL SECURITY (IPSEC)

Definition: IPSec is an open-standard suite of protocols designed to secure every packet in an IP stream traversing a network between partnering endpoints.

The Three Components:

ComponentAbbreviationWhat It Provides
Authentication HeaderAHAuthentication for data origin and integrity; protection against replay attacks.
Encapsulation Security PayloadESPConfidentiality + authentication of data's origin and integrity.
Security AssociationSAAlgorithms to enable AH and ESP to operate; framework for secure key exchanges.

📊 IPSEC OPERATING MODES

Definition: IPSec operates in two modes.

ModeWhat Is EncryptedDiagram
Transport ModeOnly the payload is encrypted and authenticated.IP Header (AH/ESP) + Encrypted Payload
Tunnel ModeThe entire packet, including the header, is encrypted.New IP Header + Encrypted (Original IP Header + Payload)

Transport Mode Diagram:

Original:  [ IP Header ] [ Payload (Data) ]
               ↓
Encrypted: [ IP Header (AH/ESP) ] [ Encrypted Payload ]

Tunnel Mode Diagram:

Original:  [ Original IP Header ] [ Payload (Data) ]
               ↓
Encrypted: [ New IP Header ] [ Encrypted (Original IP Header + Payload) ]

Memory Aid:

"Transport = Payload only. Tunnel = Whole packet."

Real-World Example:

Think of transport mode like putting a sealed envelope inside a regular envelope — the address is visible, but the contents are protected.

Think of tunnel mode like putting the whole letter (including the address) inside a new envelope with a new address.

SECTION 9: USER SEGMENTATION

🔑 USER SEGMENTATION

Definition: There are two types of segmentation.

TypeDescriptionHow It's Achieved
Internal User SegmentationSeparating internal users from each other.Most often accomplished via VLANs.
External User SegmentationSeparating external users from the corporate network.Either a wireless connection outside the corporate firewall (direct internet access) or a VLAN that provides direct internet access.

"Internal = VLANs. External = Outside firewall or guest VLAN."

🔑 VLAN, GUEST ACCESS, AND DMZ

Definition: VLANs, guest access policies, and DMZs are used to segment and secure visitor traffic.

VLAN:

  • Visitor traffic isolated and confined to only external, untrusted areas.
  • Key to VLAN security: Access Control Lists (ACLs).
  • When a client is assigned to a VLAN, all packets from that client are tagged with the VLAN number.
  • ACL is a simple lookup list that allows access to certain services.

Guest Access and Passwords:

MethodDescriptionSecurity Level
Open AccessGuest access available to anyone who can receive the wireless signal.Low
Common Guest PasswordAll visitors share a well-known password.Low
Provisioned Guest AccessEach guest gets a unique, time-limited password.High

DMZ (Demilitarized Zone):

  • Secure visitor access by placing visitors on their own DMZ segment.
  • DMZ describes an area between the internet and the corporate network.

Memory Aid:

"VLAN isolates, ACL controls, DMZ is the buffer zone."

Port-based Network Access Control (NAC) for LANs and WLANs.

4. What are the 3 entities in 802.1X?

Supplicant (client), Authenticator (switch/AP), Authentication Server (RADIUS).

5. What is EAP?

Extensible Authentication Protocol — encapsulation method for securely transporting keying material.

6. What is EAPoL?

EAP over LAN.

7. What is LEAP?

Lightweight EAP (Cisco) — unable to protect credentials.

8. What is the difference between EAP-TLS, EAP-MD5, and EAP-PEAP?

EAP-TLS: PKI certificates. EAP-MD5: password hash. EAP-PEAP: two-phase authentication.

9. What is the PTK formula?

PTK = PRF(PMK, ANonce, SNonce, MAC(AA), MAC(SA)).

10. What is RADIUS?

Remote Authentication Dial-In User Service — provides AAA services.

11. What are the 6 steps of RADIUS?

Start → Identity → Response → Exchange → Result → Access.

12. What are the 6 RADIUS benefits?

Centralized authentication, reduced administrative overhead, AAA support, scalability, dynamic access control.

13. What is the difference between IDS and IPS?

IDS: detects and flags. IPS: detects and blocks.

14. What is a WIPS?

Wireless Intrusion Prevention System.

15. What are the two types of WIPS?

Network-based (sensors) and Host-based (software).

16. What is EtherType Protocol Filtering?

Uses a protocol identifier to block specific Ethernet frames.

17. What is IP Protocol Filtering?

Uses well-known port numbers to block specific IP protocols.

18. What is Authenticated DHCP?

Supplies IP addresses only to previously authenticated clients.

19. What is 802.11i?

Standard requiring 802.1X for authentication and AES-CCMP for confidentiality and integrity.

20. What is the difference between WPA2-Personal and WPA2-Enterprise?

Personal: PSK. Enterprise: RADIUS-based authentication.

21. What is an offline dictionary attack?

Attacker captures the handshake and runs billions of password guesses offline.

22. What are the 4 WPA3 improvements?

Secure handshake (SAE), easy device addition (DPP), hotspot protection, increased key sizes (192-bit).

23. What is SAE?

Simultaneous Authentication of Equals — secure handshake that never transmits the password.

24. What is DPP?

Device Provisioning Protocol — uses QR codes to securely add IoT devices.

25. What is WPA3 192-bit mode?

Uses AES-GCMP-256, GMAC-256, ECDH-384, ECDSA-384, SHA-384.

26. What is IPSec?

Open-standard suite of protocols to secure every packet in an IP stream.

27. What are the 3 IPSec components?

AH (Authentication Header), ESP (Encapsulation Security Payload), SA (Security Association).

28. What is the difference between Transport and Tunnel mode?

Transport: payload only encrypted. Tunnel: entire packet encrypted.

29. What is a VPN?

Secure virtual point-to-point link with tunneling protocols and secure key exchange.

30. What are the 4 health checks for malware/application security?

Client integrity control, network-based services, MDM, MAM.

31. What is internal vs external user segmentation?

Internal: VLANs. External: outside firewall or guest VLAN.

32. What is a DMZ?

Demilitarized Zone — area between the internet and the corporate network.

33. What is SNMPv3?

Simple Network Management Protocol version 3 — provides integrity, authentication, encryption.

34. What are the two discovery protocols?

CDP (Cisco) and LLDP (Link Layer).

35. What is SSO?

Single Sign-On — one login for all network services.

36. What is Wi-Fi as a Service (WaaS)?

Hardware, Software, Management as a Service — cloud-based wireless.
