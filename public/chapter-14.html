CHAPTER 14: DEVICE FINGERPRINTING

SECTION 1: FINGERPRINTING BASICS & TYPES

🔑 WHAT IS FINGERPRINTING?

Definition: The process of collecting unique or semi-unique information from a device or application to identify or track it, or the user behind it.

Key Points:

  • Can be for legitimate purposes (fraud detection, analytics) or malicious ones (user tracking, device profiling).
  • Performed by collecting multiple system-level and behavioral attributes through APIs, sensors, or browser data.

The 5 Categories of Data Collected:

CategoryCommon Attributes Collected
Device HardwareModel, manufacturer, CPU type, GPU, screen resolution, RAM, battery capacity.
Software InfoOS version, security patch level, installed apps, default language, time zone.
Network InfoWi-Fi SSID/BSSID, IP address, cellular network type, carrier name.
System IdentifiersAndroid ID, Google Advertising ID (GAID), IMEI (if permitted), MAC address.
Sensor DataAccelerometer, gyroscope calibration data (used for motion-based fingerprinting).

Memory Aid:

"H-S-N-S-S" — Hardware, Software, Network, System IDs, Sensors.

🔑 THE BIG TAKEAWAY (WHY THESE EXIST)

  • iOS: Apple restricts persistent identifiers. Access to IDFA for tracking requires permission through App Tracking Transparency (ATT); IDFV is vendor-scoped, and Apple prohibits using device data to derive a unique fingerprint of a user.
  • Android: Android restricts access to persistent hardware IDs such as IMEI and device serial numbers. Tools use app/device integrity signals, emulator/root checks, analytics SDKs, and more privacy-limited identifiers.
  • Privacy: Fingerprinting can bypass user controls such as “Limit Ad Tracking” and can be difficult to reset or block. Android also limits access to identifiers such as IMEI and MAC.

Current platform references: Apple privacy and identifier rules, Apple fingerprinting policy, Android identifier guidance.

🔑 IS FINGERPRINTING BAD OR GOOD?

What Fingerprinting Can Access:

  • Location at all times.
  • Private photographs (stamped with time/location).
  • Private correspondence (emails/texts).
  • Online browsing/shopping history.
  • Audio/video at any given time.
  • Banking/credit card details.
  • Smart home security/convenience systems.
  • Contact info for spouse, children, friends, employer.

The Good:

  • Network administrators can understand what is on the network (improves performance and security).
  • Richer user experience online (customized content, convenient transactions).

The Bad:

  • Aggressively target users with unwanted ads/popups.
  • Used by cyberstalkers to track every move.

Key Takeaway:

Fingerprinting is not inherently bad, but its consequences when used for nefarious aims require increased attention and caution.

🔑 TYPES OF FINGERPRINTING

Definition: Two general categories based on where fingerprinting is done.

TypeWhere It Happens
Proximity FingerprintingOn a network.
Remote FingerprintingOnline.

Key Point: The distinction is more pronounced with wireless-enabled mobile devices than with fixed equipment.

Memory Aid:

"Proximity = Physical Network. Remote = The Internet."
SECTION 2: PROXIMITY (NETWORK) FINGERPRINTING

🔑 NETWORK ACCESS CONTROL (NAC) & ENDPOINT FINGERPRINTING

Definition: NAC restricts access to who/what can access corporate resources. Endpoint fingerprinting discovers, classifies, and monitors unknown devices.

Key Points:

  • NAC Goal: Positively authenticate users and determine if devices meet minimum security policy.
  • Purpose of Endpoint Fingerprinting: Discover, classify, and monitor unknown non-company devices (using MAC addresses).
  • Helps admins automate security profiling of endpoints (IP phones, IoT devices) using passive scanning techniques.

🔑 NETWORK SCANNING AND PROXIMITY FINGERPRINTING

Definition: Typically performed by administrators to identify devices found during network scans.

Key Points:

  • Visualize network topology.
  • Reveal ad hoc networks and unauthorized connections.
  • Reveal device type, manufacturer, OS version, and other info retrieved through discovery.

Evasion Techniques:

  • An attacker's device needs to constantly change MAC and IP addresses, and clear cookies.
  • Alternatively, the attacker masquerades as a legitimate user (forging MAC, IP, and using their cookie).
  • Rogue APs are notoriously difficult to locate because they are typically not on all the time.
SECTION 3: REMOTE (ONLINE) FINGERPRINTING

🔑 REMOTE/ONLINE FINGERPRINTING

Definition: The act of identifying a device based on a collection of common characteristics shared by all devices of a certain type.

Key Points:

  • Plays a significant role in e-commerce and search analytics.
  • Goal: Find a unique characteristic to identify the device (e.g., an iPhone vs. other smartphones).
  • HTTP is stateless: Session IDs help identify users, but they are useless for remembering the device from one visit to another. The solution is cookies.

🔑 COOKIES

Definition: A simple file containing information stored as sets of name-value pairs (e.g., userID:123456).

Key Points:

  • Website creates the cookie on first visit. Device passes it back on return visits. Website recognizes the identifier.
  • Critical information is stored in the website's own database.
  • The Problem: Cookies have a bad reputation due to privacy violations.
  • The Real Issue: Not the cookies themselves, but browsers that allow cross-site profiling.

🔑 CROSS-SITE PROFILING

Definition: Occurs when a browser accepts cookie requests from third-party advertisers on the website the user is visiting.

Key Points:

  • Allows advertisers (like Google) to track users across many sites.
  • Understands browsing habits to focus advertising.
  • Supporters: Enhances browsing experience and drives commerce.
  • Detractors: Unethical breach of privacy.

🔑 FINGERPRINTING REQUIREMENTS (THE TWO RULES)

Definition: For fingerprinting to be effective, characteristics must be:

  1. Diverse enough to be unique.
  1. Stable over time.
  1. Harder to obtain = more distinctive.

🔑 PASSIVE VS. ACTIVE FINGERPRINTING

MethodHow It WorksWhat It Analyzes / Uses
Passive FingerprintingOccurs without querying the client device. Analyzes info supplied by the device itself.HTTP headers, TCP/IP headers, 802.11 settings, OS parameters, application identification (HTTP user agent headers). IP and MAC addresses may help identify a device, but they are not stable. HTTP browser signals can include the user agent, time zone, plug-in details, and system fonts.
Active FingerprintingQueries the device in an invasive manner to access unique, stable characteristics (e.g., serial number).SNMP (discover/map network), probing network/recording responses, vulnerability scanners (e.g., OpenVAS) for OS versions and patch profiles.

Memory Aid:

"Passive = Listen. Active = Ask/Probe."
SECTION 4: UNIQUE IDENTIFIERS (THE HOLY GRAIL)

🔑 THE HOLY GRAIL OF FINGERPRINTING

Definition: A unique identifier that is everywhere, accessible, and permanent.

Key Points:

  • Developers often try to obtain hardware identifiers for their apps.
  • Alternative: Developers give the device their own identifier (like a cookie or a unique serial number downloaded with the app).

🔑 APPLE iOS IDENTIFIERS

IdentifierStatus / Description
UDI (Unique Device Identifier)Existed in early iPhones. Deprecated after iPhone 5.
IMEIExists on all GSM phones.
Advertising Identifier (IDFA)Unique to each device, but can be removed if the device is wiped.
IdentifierForVendor (IDFV)Links the device to the appropriate application vendor for analytics. Only works for devices with the vendor's app installed.

🔑 ANDROID IDENTIFIERS

IdentifierDescription
IMEIUnique hardware identifier, accessible through getDeviceID method.
Device Serial NumberUnique hardware identifier.
Android IDRandomly generated on the device's first boot and remains constant for the device's lifetime.

Key Point: It is not feasible to create an application that fingerprints all Android phones beyond a specific app.

🔑 THE ALTERNATIVE METHOD (AGGREGATION)

Definition: When UDI and IMEI are unavailable, create a unique fingerprint by aggregating multiple data sets.

Data Collected Actively via Browser:

  • Country code, device brand, device model, device carrier, IP address, language, OS name, OS version, user agent, timestamp.

Key Points:

  • Aggregating all attributes and applying weighting creates a fingerprint that is ~94% unique.
  • Flaw: This data set is considered stable for only 24 hours.

Memory Aid for Data Set:

"Country, Brand, Model, Carrier, IP, Language, OS, User Agent, Time."

🔑 SENSOR FINGERPRINTING

Definition: Using a device's physical features (microphone, accelerometer) to find unique identifiers by measuring performance.

Key Points:

  • Analyzes flaws in sensors to create a unique digital fingerprint.
  • No active software needs to be loaded on the device.
  • Every smartphone can be scanned to produce a fingerprint.

🔑 JAVASCRIPT FINGERPRINTING

Definition: Running JavaScript on a website is an excellent way to actively fingerprint devices.

Key Points:

  • JavaScript probes and retrieves many more attributes than passive HTTP scanning.
  • Users cannot adjust privacy settings to mitigate the risk or delete the fingerprint ID.
  • Other solutions: Radio signals emitted (amplifiers, mixers) and the M7 coprocessor (tracks movement/location for fitness apps).
  • The Main Flaw: The attacker must first get the user to visit a website running JavaScript.

🔑 FINGERPRINTING USERS (BIOMETRICS)

Definition: Using the device to fingerprint a person (not just the device).

Key Points:

  • Law Enforcement: Can scan/process fingerprints on the street using a smartphone.
  • Risk: Malware could constantly scan the phone for fingerprints.
  • Biometrics is the answer to the password conundrum. Everyone differs in how they interact with the UI (mouse movement, typing, voice recognition). Huge potential for positive authentication.
  • Two-factor authentication still does not guarantee that the person using the credentials is the person they claim to be. Voice recognition is also used to authenticate callers, including in financial-services call centers.
SECTION 5: SPYWARE VS. FINGERPRINTING

🔑 SPYWARE FOR MOBILE DEVICES

Definition: Software that tracks specific (and private) information about what a user is doing (sites visited, location, etc.).

The Difference:

  • Fingerprinting: Identifies a unique device.
  • Spyware: Tracks specific private information/actions.

Potentially Unwanted Applications (PUAs):

  • Most prevalent and annoying form of spyware.
  • Consumes resources (battery, bandwidth).
  • Tracks info (browsing history, GPS, contacts).
  • Changes browser settings, opening the victim to further abuse.
  • Flaw: Very few people read installation terms and conditions.

🔑 SPY SOFTWARE

Definition: Spyware that makes no attempt to hide its true nature.

Key Points:

  • Typically used by parents, employers, or phone owners to track users.
  • Legal Conditions:
    1. The entity installing/viewing must own or have legal authority over the target phone.
    1. The entity must inform any adult user that they are being monitored.
  • Key Point: Legal to monitor a company-owned smartphone as long as the employee is informed (must be in the acceptable use policy).

🔑 SPY CELLS: STINGRAY

Definition: A fake cell tower/base station used to intercept and perform MITM attacks on mobile networks (like an evil twin for cellular).

Key Points:

  • Stingray: A well-known program/fake tower.
  • IMSI Catcher: These spy base stations catch the unique IMSI (International Mobile Subscriber Identity) number from a phone.
  • Used by law enforcement/intelligence to track mobile users.
  • How it works: Boosts power higher than real mobile operators' signals to trick phones into connecting.

Memory Aid:

"Stingray = Fake Cell Tower. IMSI Catcher = Grabs your ID."

🔑 FINGERPRINTING ON MODERN CELLULAR NETWORKS (4G/5G)

The 4G Vulnerability:

  • Cellular networks are not uniform: 2G, 3G, 4G, and 5G are used in different places.
  • To build a connection, devices must pass a list of their capabilities/requirements to the base station.
  • The Flaw: The initial connection (where identity and device capabilities are transferred) occurs unencrypted (clear text).
  • Result: Smartphones, IoT devices, routers send capabilities in clear text, allowing eavesdroppers to fingerprint the device or launch MITM attacks.

What Attackers Can Do with 4G Plaintext:

  • Map devices connected to a given network.
  • MNmap: Researchers used this 4G/5G plaintext information to map connected devices and fingerprint their likely type or operating system.
  • Fingerprint devices (tell if it's iOS, Android, IoT, or a router).
  • Baseband Manufacturers: There are only 5 main baseband manufacturers (Huawei, Intel, Mediatek, Qualcomm, Samsung). They don't use the same mandatory capabilities, aiding fingerprinting.

Advanced MITM Attack (4G):

  • Use MITM replay to hijack device info before security is applied.
  • Modify device capabilities (e.g., suppress the speed at which data is sent).

The 5G Fix:

  • In Release 14 of the 5G standard, encryption is applied before the device sends its capability information to the network, preventing eavesdropping.

Memory Aid:

"4G = Clear Text Handshake. 5G (Rel 14) = Encrypted Handshake."

✅ THE CORE TRUTH
Fingerprinting is a double-edged sword: it can improve security and user experience, but it also enables aggressive tracking and privacy loss. Whether done via proximity (network) or remote (online) methods, the goal is to find a stable, unique identifier. While Apple and Android restrict hardware IDs, attackers and advertisers increasingly rely on aggregated attributes, sensor flaws, and unencrypted cellular handshakes (4G) to identify and track devices.
